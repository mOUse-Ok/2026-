# README Figures: Data, Provenance, and Claim Boundaries

## Scope

This index is the audit record for every asset in `docs/assets/` generated by
`docs/scripts/generate_readme_figures.py`. Its sole final experimental source is
[`../final-readme-evidence-v2.md`](../final-readme-evidence-v2.md) (V2). No new
benchmark, strategy comparison, or code-path experiment was run for these
figures. The only figure that reads a raw artifact is the Rescue timeline; it
reads the already-closed `rescue_on_4/memory_trace.jsonl` to transcribe its
per-decode-step mechanism trace.

`Current HEAD` means commit `01817a0`, as recorded by V2. `Historical` means a
closed result retained by V2 for mechanism context; it is not silently promoted
to a current-HEAD result. Where V2 does not record a single historical commit or
experiment directory, this index says so instead of reconstructing one.

## Citation and reuse rules

- Caption a historical figure as **historical** every time it is used.
- Keep the tested setup with all numeric current-HEAD figures: fixed CPU/Qwen,
  7040 MiB cold-cache conditions where V2 records them.
- Do not replace “associated with” with “caused” for COLD results.
- Do not call the Rescue deltas `-5.24%` / `-20.85%` a causal speedup; those are
  not charted as a performance win here.
- Do not infer physical page reclaim from a successful `madvise`, or residency
  from a first-use event.
